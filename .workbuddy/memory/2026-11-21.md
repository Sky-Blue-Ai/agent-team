## 竞态覆盖 bug（用户报告"知识库空页面"）与根治
- 现象: 脚本写入19条后,用户浏览器旧标签页显示空,且 data.json 的 kb 被冲回 0
- 根因: 多标签页/多浏览器竞态——旧页面内存里是写入前的空快照,任一 save 都用旧数据整体覆盖服务端新数据
- 根治: 引入单调递增版本号 `_rev` 乐观锁
  - server.py: EMPTY 加 _rev=0;normalize 保留并转 int;POST /api/data 若客户端显式带 _rev 且 < 服务端当前值 → 返回 409 + {conflict,rev,data:最新},拒绝覆盖;无 _rev 的写入(外部脚本)放行;成功写入时 _rev+1 返回 {ok,rev}
  - app.js: 增 serverRev;load 记录服务端 _rev;save 带 this.data._rev=serverRev,收 200 用响应 rev 更新、收 409 调 _adoptConflict 用最新数据覆盖本地+renderAll+toast;新增 syncFromServer() 静默同步,focus/visibilitychange/5s 定时触发,rev 更新则追平;导入/重置后仍 reload
  - seed_kb.py(新建,放 site 目录,可复用恢复19条): 每次执行 _rev+1
- 关键教训: 初始 rev=0 无法区分"同样0的旧快照",故 seed 脚本必须自增;判断用 `has_in_rev` 而非 in_rev truthy(否则 rev=0 漏判)
- 验证: API 三场景(陈旧409保住19条/正常200自增/无版本放行)全过;无头Chrome 聚焦同步测试 3/3(外部改18条→旧页聚焦后自动追上18);最终交付态 rev=1/kb=19/2产品/6skill/4agent/3rule/7日志/羽乐/白天
- 数据备份: 可靠源 /tmp/pf_data_before_kb.json(kb=0但其它完整);/tmp/pf_data_clean.json 是残缺测试产物勿用
