
## 全栈版部署到 GitHub Pages (2026-11-22 凌晨)
- 用户要求"读取本地最新代码，编译部署到 github"。本地已有大量未提交改动：架构从纯前端升级为**前端 + Python 后端**。
- 新架构要点：
  - `server.py`：本地服务，静态文件 + `/api/data`(读写 data.json，`_rev` 乐观锁防多标签页覆盖) + `/api/agent/*`(AI 代理) + `/api/ai/generate`
  - `data.json`：19 条知识库 / 6 Skill / 4 Agent / 3 Rule / 2 产品 / 7 日志，`_rev=1`
  - 前端导航扩为 9 个视图：流水线看板、灵感与战略、产研交付台、增长与调优、知识库、SOP 流程、Skill Hub、Agent Hub、Rule Hub
  - app.js 有 localStorage 降级(fetch /api/data 失败即降级)，所以静态部署仍可用，只是数据各浏览器独立、AI 不可用
- 部署决策(用户确认)：
  - 推静态版到 Pages，保留 localStorage 降级
  - data.json **一起提交**到公开仓库(用户明确同意)
  - `ai_config.json` 与 `__pycache__/`、`*.pyc` 加入 .gitignore，密钥绝不入库(已扫描确认无 sk- 泄露)
- 部署结果：main 提交 12219f6，gh-pages 提交 a45d313；线上 index.html 126495B / app.js 132223B 与本地完全一致
- 验证：本地全栈 18/18(含 9 列等高、知识库 19 条、Hub 统计、AI 未配置状态)；纯静态模式 5/5(降级到 localStorage 正常持久化)；线上 18/18(所有视图可开、零报错)
- 注意：线上 `/api/data` 必然 404 一次，这是降级探测的正常行为，不是故障；空数据时看板显示空态提示而不渲染 9 列，属预期
- 用户侧提醒：线上地址看不到本地的 19 条知识库等数据(各浏览器独立)；要共享数据+AI 必须用本地 `启动工作台.command`
